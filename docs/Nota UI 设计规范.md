## 1. 引言

### 1.1 目的

本文档定义 Nota 的界面视觉与交互规范。它填补的是设计基线中的一段空白：SRS 的 UI-01～UI-08 只到「主窗口应包含…」这一层，架构文档 §5.1 只有一张组件职责清单，两者都没有定义布局、尺寸、配色、状态与交互。

本文档是**M1～M5 的界面实现依据**：每个界面元素在本文档中都能找到取值或规则，实现时不需要再猜。

### 1.2 范围

覆盖 **V1.0 全量界面**，并为 V1.1／V1.2／V2.0 预留可扩展的容器与菜单位，但不细化后者。

| 覆盖     | 内容                                                                                     |
| -------- | ---------------------------------------------------------------------------------------- |
| 布局骨架 | 六区域划分、尺寸、底部面板行为、标签溢出、边界状态                                       |
| 设计令牌 | 颜色／密度／字体三组，浅深两套取值，含对比度实测                                         |
| 组件清单 | 15 个 V1.0 前端组件的职责与里程碑归属                                                    |
| 三栏内容 | 菜单栏（7 个顶层菜单逐项）、工具栏（8 个按钮）、状态栏（含溢出优先级）                   |
| 图标     | 图标库选型、接入方式、20 项图标名清单（§6.5）                                            |
| 交互规则 | 标签状态、焦点与键盘导航、快捷键归属、主题与字体应用、提示与错误、高 DPI                 |
| 扩展位   | 语言菜单（V1.1）、代码折叠菜单项（V1.1）、在文件中查找页签（V1.2）、宏与插件菜单（V2.0） |

**不覆盖**：具体控件的像素级视觉稿（本文档给令牌与规则，不给切图）；V2.0 界面的详细设计（架构文档 §5.4 已承认那 4 组需求尚无组件设计，界面设计同样不具备前提）。

### 1.3 权威边界

本文档加入后，设计基线为四份文档，各自权威范围如下：

| 文档                               | 权威范围                                                                       |
| ---------------------------------- | ------------------------------------------------------------------------------ |
| 《Nota 软件需求规格说明书》   | **需求定义**：FR／UI／HI／SI／CI／DC／OR／PR／AC 各条内容与优先级              |
| 《Nota 架构与技术栈设计文档》 | **技术架构与版本计划**：技术选型、组件与接口设计、第 12 章的版本归属与需求归属 |
| **本文档**                         | **界面视觉与交互**：布局、令牌、组件清单、三栏内容、交互规则                   |
| 《Nota 应用实施计划》         | **实施顺序**：里程碑分解、出口标准、风险登记                                   |

冲突时：需求内容以 SRS 为准，版本归属以架构文档第 12 章为准，界面取值与交互以本文档为准，实施顺序以实施计划为准。四份文档之间已存在的差异见 §9.2。

## 2. 设计原则

以下七条由项目既有约束推出，是本文档后续所有取舍的依据。

| 编号   | 原则                                                                   | 依据                                                                                                                                                                                                                                           |
| ------ | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **P1** | 骨架自持，组件库只出现在对话框与反馈层（唯一例外是 `n-icon`，见 §6.5） | 菜单栏、标签栏、状态栏在候选组件库中均无对应物，强行套用需覆盖其尺寸体系；Naive UI 的价值集中在表单与反馈（AD-11 的适用范围据此收窄，见 §9.2）。`n-icon` 例外不违背本原则：它只是 1em 见方、`fill: currentColor` 的 `<i>` 容器，不携带尺寸体系 |
| **P2** | 一个令牌源，三处消费                                                   | 主题（FR-37）与字体（FR-38）必须运行时切换；若界面配色与编辑器配色各有一源，"界面深色但编辑器浅色"这类漂移无法从结构上避免                                                                                                                     |
| **P3** | 信息密度优先，但可访问性不可让                                         | G-01 轻量快速与五类用户中的开发／运维／数据分析三类都要求高密度；同时 DC-04、UI-07 要求 Unicode 与高 DPI 可用，对比度不得因压缩尺寸而失守                                                                                                      |
| **P4** | 状态可见优先于界面简洁                                                 | 未保存标记不需要悬停即可见；不可用按钮置灰而非隐藏；面板折叠后仍保留页签条                                                                                                                                                                     |
| **P5** | 不加未被要求的功能                                                     | 无 FR／HI／OR 支撑的功能一律列入 §9.3 范围外，不进 V1.0                                                                                                                                                                                        |
| **P6** | 未验证的不写成结论                                                     | 无实测支撑的判断标入 §9.1 待验证，不以"应该没问题"的形式出现在正文                                                                                                                                                                             |

## 3. 布局骨架

### 3.1 区域划分

窗口自顶向下六个区域，尺寸取自 §4.3 密度令牌。

| 区域     | 高度                      | 弹性                  | 可见性                 |
| -------- | ------------------------- | --------------------- | ---------------------- |
| 菜单栏   | 24                        | 固定                  | 常驻（UI-01）          |
| 工具栏   | 28                        | 固定                  | 常驻                   |
| 标签栏   | 26                        | 固定                  | 常驻，单标签时亦显示   |
| 编辑区   | —                         | `flex: 1`，最小高度 0 | 常驻                   |
| 底部面板 | 26（折叠）／内容区默认 80 | 固定＋可拖拽          | 常驻（折叠态仅页签条） |
| 状态栏   | 22                        | 固定                  | 常驻（UI-01、UI-06）   |

窗口最小尺寸 **640 × 400**。默认尺寸与标题见 §8.3。

V1.0 **没有侧边栏／活动栏**：跨文件搜索结果与插件管理都在底部面板或对话框中呈现，不引入左右栏位。

### 3.2 底部统一面板（DockPanel）

**设计决定：查找／替换与跨文件搜索共用同一个容器，内部以页签区分。**

| 页签         | 内容                                                         | 里程碑 |
| ------------ | ------------------------------------------------------------ | ------ |
| 查找 / 替换  | 查找框、替换框、上下导航、Aa／正则／全词开关、替换与全部替换 | M4     |
| 在文件中查找 | 目录、文件类型、关键字、搜索按钮、结果树                     | M7     |
| （后续）     | 打印预览（M10）等按需追加页签                                | —      |

行为规则：

- **折叠态保留 26px 页签条**（P4）。页签条既是"面板当前在做什么"的状态显示，也是再次展开的入口。
- 面板内容区默认高 80，**可拖拽调整，并记住上次值**；双击分隔条在「默认高度／折叠」间切换。
- 编辑区保底可见 **3 行**；面板拖到再高也不把编辑区挤没。
- 页签切换各自保留状态（查找词、搜索结果），互不重置。

选此方案而非"编辑区内嵌浮条"或"浮动对话框"的理由：M4 建一次容器，**M7 只需加一个页签**；另两种方案到 M7 时都必须再建一套底部容器。

### 3.3 标签溢出

**单行 + 横向滚动 + 两侧溢出箭头**，不做多行标签栏。

理由：窗口高度固定，多行标签栏会让"能看见几行代码"随打开文件数变化；横向滚动则不影响编辑区高度。切换标签时自动将目标标签滚入可视区。AC-03 要求同时打开 10 个以上文件，此规则为该验收项的界面前提。

### 3.4 边界状态

| 状态                 | 行为                                                                                                           |
| -------------------- | -------------------------------------------------------------------------------------------------------------- |
| **启动无可恢复文件** | 直接创建「未命名 1」空标签，**不做欢迎页**。与 FR-04 同一路径，零新增组件；菜单栏常驻，"文件 → 打开"仍可发现。 |
| **关闭最后一个标签** | 自动新建「未命名 N」。因此不存在"无标签空态"这一状态，少一个组件。                                             |
| **启动焦点**         | 直接在编辑区，可立即输入。FR-01 的"快速启动"在交互上即此含义。                                                 |
| **窗口过窄**         | 工具栏放不下的按钮收进尾部 `»` 溢出菜单；菜单栏顶层菜单同样收进 `»`；状态栏按 §6.3 的优先级依次隐藏。          |
| **不可用操作**       | 工具栏按钮**置灰而非隐藏**——隐藏会让按钮位置跳动，破坏位置记忆。                                               |

## 4. 设计令牌

### 4.1 令牌管线

**一个源，三处消费。**

```text
ThemeTokens 类型 + 内置浅/深两套值（tokens.ts）
        │
        ├─ tokensToCssVars(tokens)      → 根元素 CSS 自定义属性 → 骨架组件读 var(--sp-*)
        ├─ tokensToEditorTheme(tokens)  → CodeMirror EditorView.theme
        └─ tokensToNaiveOverrides(tokens) → Naive UI n-config-provider :theme-overrides
```

- 三个派生函数均为**纯函数**，由 M0 的 Vitest 直接覆盖，不需要启动界面。
- 换主题＝替换一个令牌对象；改字体／字号＝合并覆盖层 `mergeTokens(base, userConfig)`。
- **主题文件（架构文档 §7.1）与内置主题走同一条路径**：从文件解析出的也是 `ThemeTokens`，不另设机制。
- 切换主题时**只替换令牌对象，不重挂组件**；CodeMirror 主题通过 `Compartment` 热替换，避免重建编辑器（会丢失撤销历史与滚动位置）。

`tokensToNaiveOverrides` 必须覆盖的具体项如下。Naive UI 的默认值比本规范的紧凑密度宽松得多（已核实其 `lib/_styles/common/_common.js`），不覆盖就会出现"骨架紧凑、对话框臃肿"的割裂：

| Naive UI 默认值                                                                 | 本规范取值                                             | 是否覆盖                                                                                                                         |
| ------------------------------------------------------------------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| `fontFamily: "v-sans, system-ui, …, \"Segoe UI\", sans-serif, …"`               | `--sp-font-ui`（§4.4）                                 | **是**                                                                                                                           |
| `fontFamilyMono: "v-mono, SFMono-Regular, Menlo, Consolas, Courier, monospace"` | `--sp-font-mono`（§4.4）                               | **是**                                                                                                                           |
| `fontSize: 14px`；`fontSizeMini/Tiny/Small/Medium: 12/12/14/14px`               | `--sp-font-size-ui` 12px、`--sp-font-size-status` 11px | **是**                                                                                                                           |
| `heightMini/Tiny/Small/Medium: 16/22/28/34px`                                   | `--sp-control-h` 18px                                  | **是**                                                                                                                           |
| `borderRadius: 3px`、`borderRadiusSmall: 2px`                                   | `--sp-radius` 3px                                      | **否——本来就一致**                                                                                                               |
| `lineHeight: 1.6`                                                               | 无需覆盖                                               | **否**——该值管的是 Naive UI 组件自身的行高（设置对话框里 1.6 反而合适），与编辑器的 `--sp-line-height-editor` 是两回事，不要混用 |

### 4.2 颜色令牌（语义命名）

命名一律用**语义**而非外观（`--sp-text-dim` 而非 `--sp-gray-500`）：同一个令牌名在浅色下是深灰、在深色下是浅灰，两套主题因此共用同一套令牌名。

| 令牌                    | 用途                             | 浅色             | 深色             |
| ----------------------- | -------------------------------- | ---------------- | ---------------- |
| `--sp-bg-chrome`        | 菜单栏、工具栏、面板内容区       | `#f3f3f3`        | `#2c2c2c`        |
| `--sp-bg-tabstrip`      | 标签栏、面板页签条（未活动）     | `#e9e9e9`        | `#242424`        |
| `--sp-bg-surface`       | 活动标签、编辑区                 | `#ffffff`        | `#1c1c1c`        |
| `--sp-bg-status`        | 状态栏                           | `#eeeeee`        | `#2c2c2c`        |
| `--sp-bg-hover`         | 按钮／菜单项悬停                 | `#e0e0e0`        | `#3b3b3b`        |
| `--sp-text`             | 界面主要文字                     | `#1f1f1f`        | `#e6e6e6`        |
| `--sp-text-dim`         | 次要文字（标签、状态栏字段）     | `#666666`        | `#9a9a9a`        |
| `--sp-text-disabled`    | 禁用文字                         | `#a0a0a0`        | `#6a6a6a`        |
| `--sp-border`           | 区域分隔线、控件边框             | `#d2d2d2`        | `#3e3e3e`        |
| `--sp-accent`           | 强调色、活动标签指示条、开关开启 | `#2f6fd0`        | `#6ea8fe`        |
| `--sp-accent-soft`      | 当前行高亮、选中态淡底           | `#e7effb`        | `#25344a`        |
| `--sp-on-accent`        | **强调色底上的文字**（主按钮）   | `#ffffff`        | `#10233d`        |
| `--sp-focus-ring`       | 键盘焦点描边                     | 同 `--sp-accent` | 同 `--sp-accent` |
| `--sp-editor-text`      | 编辑区正文                       | `#1f1f1f`        | `#e6e6e6`        |
| `--sp-editor-gutter`    | 行号文字                         | `#a8a8a8`        | `#5f5f5f`        |
| `--sp-editor-caret`     | 光标                             | `#1f1f1f`        | `#e6e6e6`        |
| `--sp-editor-selection` | 选中文本底色（叠加在编辑区上）   | accent 22%       | accent 28%       |
| `--sp-search-hit`       | 查找命中（非当前）               | `#ffc400` 45%    | `#ffc400` 32%    |
| `--sp-search-active`    | 查找命中（当前）                 | `#ff8c00` 65%    | `#ff8c00` 50%    |

两条由实测推出的决定：

1. **`--sp-on-accent` 必须是每套主题各自持有的令牌，不能是全局白色。** 深色主题下白字在 `#6ea8fe` 上仅 2.42:1，不达标；改为 `#10233d` 后为 6.54:1。
2. **`--sp-text-dim` 浅色值由 `#6b6b6b` 调为 `#666666`。** 原值在状态栏上 4.59:1 通过，但在标签栏 `#e9e9e9` 上仅 4.39:1，不达标；调整后最差 4.73:1。

**成功／警告／错误三种语义色不由本规范定义**，沿用 Naive UI 默认值。V1.0 中用到它们的场景（提示、崩溃恢复通知）全部位于 Naive UI 组件内部，其默认值已为可访问性调校；自行定义只会多出一处需要同步的源。

#### 4.4.1 关于 vfonts：判断为不引入

Naive UI 官方 README 的 `### Fonts` 段推荐 `vfonts`（作者同为 `07akioni`，MIT）。**本规范判断为不引入**，依据是实测结果而非偏好。

**vfonts 不含中日韩字形。** 读取包内 9 个 TTF 的 `maxp` 表，字形数为 **851～1294**——IBMPlexMono 851、IBMPlexSans 930、OpenSans 938、RobotoSlab 1155、Roboto 1294。含中日韩的字体至少两万字形起。其 README 亦只提供 `v-sans` 与 `v-mono` 两个族别名，等宽仅 FiraCode 一个。

**因此 vfonts 与「Microsoft YaHei」不是二选一的关系。** 中文界面（UI-08、DC-04、FR-53）无论如何都必须依赖系统 CJK 字体；引入 vfonts 只是在 YaHei 之外再加一套拉丁字体，依赖只增不减。

其余理由：

| #   | 理由                                                                                                                                                                                                           |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Windows 上 **Segoe UI 是原生 UI 字体**：0 字节、0 解析开销、与系统控件观感一致                                                                                                                                 |
| 2   | G-01（冷启动 ≤ 1.5 秒）与 AC-01 的运行预算不为可选拉丁字体付出体积；DC-10 离线优先同理                                                                                                                         |
| 3   | **不引入不会坏**：Naive UI 的默认栈是 `v-sans, system-ui, …, "Segoe UI", sans-serif, …`，`v-sans` / `v-mono` 之后有完整的系统回退（已核实源码），且本规范本来就要用令牌覆盖其 `fontFamily`（§4.1）             |
| 4   | **连带效应**：编辑器等宽若由 Consolas 换成 FiraCode，§9.1 第 1 项「中日韩字符是否正好占 2 个拉丁字符宽」的答案会随之改变——两者字符前进宽度不同。这会把一个待验证项变成两个，并在 M1 最需要确定性处引入不确定性 |

**唯一的反向理由**：跨机器一致性。Segoe UI 在 Windows 10 与 11 上版本不同（后者为 Segoe UI Variable），内嵌字体可得到一致渲染。本规范判断该收益不足以抵上述四条；若日后确认需要一致渲染，再改为引入 vfonts，并把 §9.1 第 1 项按 FiraCode 重测。

**字体分工（结论）**：

| 字符范围         | 来源                                                       |
| ---------------- | ---------------------------------------------------------- |
| 拉丁、数字、符号 | 系统 UI 字体 Segoe UI；等宽用 Consolas（系统自带）         |
| 中日韩           | 系统 CJK 字体 Microsoft YaHei（系统自带，vfonts 无法替代） |

### 4.5 对比度校验

按 WCAG 2.1 相对亮度公式实测，全部达标（复算方式见 §9.1）：

| 检查项                      | 阈值 | 浅色      | 深色      |
| --------------------------- | ---- | --------- | --------- |

| 次要文字 / 标签栏           | 4.5  | 4.73 : 1  | 5.52 : 1  |

### 6.5 图标

#### 6.5.1 图标库

**Naive UI 官方推荐的图标库是 [xicons](https://www.xicons.org)，其在 Vue 3 下的包族为 `@vicons/*`。** 该推荐出自 Naive UI 官方 README 原文（"Naive UI recommends using xicons as icon library"），且 `@vicons/*` 的 README 声明自身为 "A part of xicons project"，作者 `07akioni` 与 naive-ui 为同一人。各包均 MIT 协议，当前版本 0.13.0（2024-12-20 发布，不受 pnpm 的 24 小时 `minimumReleaseAge` 门禁影响）。

本项目选用 **`@vicons/fluent` 0.13.0**（Fluent UI System Icons）：

| #   | 依据                                                                                                     |
| --- | -------------------------------------------------------------------------------------------------------- |
| 1   | **15px 下清晰**。紧凑密度把图标压到 15px，本规范拟用的图标全部为填充型（实测 8/8），缩放不产生亚像素描边 |
| 2   | **Regular / Filled 成对**，包内共 20144 个图标，覆盖最广。选中态、勾选菜单项、开关开启都需要成对图标     |
| 3   | Windows 优先（DC-05），与微软自家图标体系一致                                                            |

未选用的三个候选，原因是**实测值而非印象**：

| 图标集              | 实测结果                                                                                  | 未选原因                                                                                                            |
| ------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `@vicons/ionicons5` | 拟用图标全部为描边型（8/8）；viewBox 512、`stroke-width: 32` → **15px 下有效描边 0.94px** | 描边落到 1px 以下即成亚像素，100% DPI 下渲染发虚、浓淡不匀；且包内**无"文件+加号"**，「新建」只能退化成普通文档图标 |
| `@vicons/tabler`    | viewBox 24、`stroke-width: 2` → 15px 下有效描边 1.25px                                    | 偏细；且无 Regular / Filled 成对                                                                                    |
| `@vicons/antd`      | 填充型，15px 下清晰                                                                       | 包内图标最少（1582 个），视觉风格偏中后台，与桌面工具定位不符                                                       |

> **`@vicons/ionicons5` 正是 Naive UI 自身文档与示例默认使用的图标集。** 本规范与它结论不同是有实测依据的（上表第一行），不是疏漏；"官方示例用什么就用什么"在这个尺寸下恰好是错的选择。

#### 6.5.2 接入方式

| 项目     | 规则                                                                                                                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 依赖     | `@vicons/fluent` 0.13.0，**运行时依赖**（非 devDependency）                                                                                                                                                                    |
| 包装     | 经 Naive UI 的 `n-icon` 渲染                                                                                                                                                                                                   |
| 尺寸     | **由令牌驱动，不在调用点写死**。`n-icon` 的样式为 `height / width / line-height: 1em` 且 `fill: currentColor`（其 `size` 属性也只是映射为 `font-size`），因此只需在容器上给出 `font-size: var(--sp-icon)` 与颜色，图标自动跟随 |
| 颜色     | 始终以 `currentColor` 继承，**不传 `color` 属性**，使图标与所在区域的文字令牌保持一致；激活态由容器改用 `--sp-accent`                                                                                                          |
| 封装组件 | **不新增**。`n-icon` 已完成尺寸与颜色的归一，再包一层是没有消费者的抽象                                                                                                                                                        |
| 变体用法 | 默认 **Regular**；**Filled** 仅用于选中／激活态（面板当前页签、勾选中的菜单项、开关开启）                                                                                                                                      |

`n-icon` 是 P1 的唯一例外（见 §2），理由见该表。

## 7. 交互规则

### 7.1 标签

| 状态             | 右侧指示               | 理由                                                                   |
| ---------------- | ---------------------- | ---------------------------------------------------------------------- |
| 活动（已保存）   | 常显 `×`               | 顶部 2px 强调色条＋surface 底色＝活动状态                              |
| 未活动（已保存） | 常显 `×`               | 紧凑密度下不值得为省几像素把关闭按钮藏进悬停                           |
| 悬停             | 背景变 `--sp-bg-hover` | **只有背景变化**，不做位移或放大——避免鼠标划过时整排标签抖动           |
| **未保存**       | 常显 `●`，悬停时变 `×` | `●` 不需要悬停即可见："这个文件改了没存"绝不能是悬停才暴露的信息（P4） |

中键点击任意标签＝关闭（Windows 惯例）。

### 7.2 焦点与键盘导航

| 项目     | 规则                                                                                                     |
| -------- | -------------------------------------------------------------------------------------------------------- |

### 7.3 快捷键归属

实施计划 M5 的风险栏登记「快捷键体系与 CodeMirror 命令映射容易冲突，需在开工前确定按键方案的归属」。本节即该划分：

| 表                                | 键位                                                                                                    | 生效条件                   |
| --------------------------------- | ------------------------------------------------------------------------------------------------------- | -------------------------- |
| **全局表**（应用级，菜单可显示）  | Ctrl+N／O／S／Shift+S／W、Ctrl+F／H、Ctrl+Shift+F（V1.2）、Ctrl+,、F1、Alt+F4                           | 始终生效，编辑区聚焦时亦然 |
| **编辑器内表**（CodeMirror 接管） | Ctrl+Z／Y／X／C／V／A、Ctrl+Shift+K／D／J、Alt+↑/↓、Ctrl+←/→、Home／End／PgUp／PgDn、Alt+鼠标（列选择） | 仅在编辑区聚焦时生效       |

## 8. 对实施的影响

### 8.1 启动背景色（对 `tauri.conf.json` 与 Rust 侧的要求）

Tauri 窗口在 WebView 画出第一帧之前就已可见，深色主题用户会看到一次白色闪光。

**机制**：把窗口的 `backgroundColor` 设为**上次使用主题的编辑区底色**（浅 `#ffffff` / 深 `#1c1c1c`），由 Rust 侧在创建窗口时读取配置决定。

已核实：`backgroundColor` 是 Tauri 2.12 `WindowConfig` 的合法属性（`node_modules/@tauri-apps/cli/config.schema.json`），描述为 "Set the window and webview background color"，并注明 **Windows 平台上 alpha 通道会被忽略**，因此取值必须是不透明十六进制色。

**不采用**"隐藏窗口、就绪后再 show"：那会让 AC-01「冷启动 ≤ 1.5 秒」的主观感受更慢——用户盯着的是空桌面而非正在出现的界面。用正确的初始背景色换取"窗口立刻出现"，更符合 G-01。

此项使 M1 的界面任务超出纯前端范围（需改 `tauri.conf.json` 并由 Rust 侧读主题）。

### 8.2 窗口尺寸与标题

当前 `tauri.conf.json` 为 800 × 600。按 §3.1 的最小尺寸 640 × 400 与紧凑密度，建议默认窗口设为 **1200 × 800**，并记录并恢复上次的窗口尺寸与位置。标题格式：`文件名 — Nota`，未保存时前缀 `●`。
