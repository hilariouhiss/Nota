## 1. 引言

### 1.1 目的

本文档定义 ScribaPad 的功能需求、外部接口需求、性能需求、设计约束和软件系统属性。  
本文档面向产品经理、开发人员、测试人员、项目管理人员和最终用户代表，作为设计、开发、测试、验收和变更控制的依据。

ScribaPad 的核心目标是：

> 用最低的启动和操作成本，完成大多数文本、配置、日志、脚本和代码编辑任务。

### 1.2 范围

ScribaPad 是一款轻量、快速、可扩展的桌面文本/代码编辑器，主要面向 Windows 平台，后续可扩展至 Linux、macOS。

本版本范围包括：

- 快速启动与低资源占用
- 多标签文本编辑
- 语法高亮
- 查找替换与跨文件搜索
- 编码与换行符处理
- 会话恢复与自动备份
- 插件扩展
- 主题、快捷键和便携模式

本版本不包括：

- 完整 IDE 的编译、调试、项目管理功能
- 大型团队协作平台
- 强制云同步
- 复杂数据库管理功能

## 2. 总体描述

### 2.1 产品前景

#### 2.1.1 系统接口

ScribaPad 作为独立桌面应用运行，与以下系统组件交互：

- 操作系统文件系统：打开、保存、另存、备份、监视文件变化。
- 系统剪贴板：复制、剪切、粘贴。
- 系统打印服务：打印与打印预览。
- 命令行：通过参数打开文件、跳转行号。
- 系统通知：文件变更、崩溃恢复、插件状态提示。
- 安装版可写入注册表；便携版不得强制写入注册表。

#### 2.1.2 用户接口

主界面包括：

- 菜单栏
- 工具栏
- 标签栏
- 编辑区
- 状态栏
- 查找/替换面板
- 跨文件搜索面板
- 插件管理面板
- 设置与主题对话框

界面应支持浅色、深色主题，支持高 DPI。

#### 2.1.3 硬件接口

- 键盘：快捷键、组合键、宏录制。
- 鼠标：选择、拖拽、右键菜单、列编辑。
- 显示器：支持 1366×768 及以上分辨率，高 DPI 下不模糊。
- 磁盘：本地文件读写，支持便携存储设备。

#### 2.1.4 软件接口

- Windows 10/11 优先。
- 可选 Linux、macOS 版本。
- 支持 Unicode、UTF-8、GBK、ANSI、UTF-16 等编码。
- 提供插件 API。
- 可集成系统默认浏览器、邮件客户端和打印服务。

#### 2.1.5 通信接口

- 核心编辑功能不依赖网络。
- 可选检查更新，使用 HTTPS。
- 可选插件市场，使用 HTTPS。
- 不强制云同步。
- 不自动上传用户文件内容。

#### 2.1.6 内存约束

- 空闲内存占用应保持较低。
- 普通编辑场景下不得因内存问题频繁卡顿。
- 大文件模式可限制撤销栈、语法高亮或实时解析。

#### 2.1.7 操作

- 普通模式：安装到系统，配置保存在用户目录。
- 便携模式：配置、插件、会话保存在程序目录。
- 支持离线使用。
- 支持多实例或单实例配置。

#### 2.1.8 场地适配需求

- 支持中文、英文界面。
- 支持高 DPI、多显示器。
- 支持不同系统区域设置下的编码识别。
- 支持企业环境中的离线安装和便携部署。

### 2.2 产品功能

ScribaPad 的高层功能包括：

1. 快速启动与退出。
2. 文件新建、打开、保存、另存、关闭。
3. 多标签编辑。
4. 基础文本编辑。
5. 语法高亮与代码折叠。
6. 查找、替换、正则表达式。
7. 跨文件搜索与替换。
8. 编码识别与转换。
9. 换行符识别与转换。
10. 宏录制与回放。
11. 插件管理与扩展。
12. 主题、字体、快捷键设置。
13. 会话恢复与崩溃恢复。
14. 自动保存与备份。
15. 大文件查看。
16. 命令行打开与跳转。
17. 打印与导出。
18. 便携模式。
19. 多语言界面。

### 2.3 用户特征

| 用户类型     | 特征                 | 主要需求                         |
| ------------ | -------------------- | -------------------------------- |
| 开发人员     | 熟悉快捷键和代码编辑 | 写代码、查日志、改配置、批量替换 |
| 运维人员     | 常处理日志和配置文件 | 大文件查看、跨文件搜索、编码转换 |
| 数据分析人员 | 处理 CSV、JSON、SQL  | 列编辑、正则替换、编码处理       |
| 普通办公用户 | 替代记事本           | 简单编辑、保存、查找替换         |
| 插件开发者   | 需要扩展接口         | 插件 API、事件、菜单扩展         |

### 2.4 约束

- 启动速度必须明显快于重型 IDE。
- 核心编辑功能不依赖网络。
- 插件异常不得导致主程序崩溃。
- 默认配置应简单，用户无需配置即可使用。
- 便携模式不得强制写入系统注册表。
- 全面支持 Unicode，避免中文乱码。
- 应支持 Windows 10/11。
- 界面应支持高 DPI。
- 产品应可离线安装和使用。

### 2.5 假设与依赖

- 用户具备基本文件操作能力。
- Windows 是主要目标平台。
- 插件生态可由官方或社区维护。
- 免费或开源模式由业务策略决定。
- 大文件性能依赖硬件配置。
- 编码识别不可能 100% 准确，需提供手动选择。

### 2.6 需求分配

各版本的需求范围、技术重点与语法支持范围**统一定义在架构文档第 12 章「版本演进规划」**，该章是版本计划的唯一权威来源。

本节此前曾自行列出另一套版本划分（V1.0/V1.1/V1.2），与架构文档及本附录 B 三者互相冲突；现统一改为引用，避免多处维护产生分歧。

需求优先级（M/S/C）的含义见附录 B。

### 3.4 逻辑数据库需求

ScribaPad 需要持久化以下数据：

| 数据实体 | 内容                                 | 存储方式           | 生命周期   |
| -------- | ------------------------------------ | ------------------ | ---------- |
| 配置文件 | 字体、主题、快捷键、语言、自动保存   | TOML/JSON          | 长期       |
| 会话文件 | 打开文件、光标、标签顺序、未保存内容 | 专用格式           | 退出后保留 |
| 最近文件 | 文件路径、时间                       | 配置或独立文件     | 可清理     |
| 备份文件 | 未保存内容、崩溃恢复数据             | 临时目录或程序目录 | 恢复后清理 |
| 插件配置 | 插件启用状态、参数                   | 插件目录或配置目录 | 长期       |
| 主题文件 | 颜色、样式                           | 主题文件           | 长期       |
| 宏文件   | 录制操作                             | 宏目录             | 长期       |
| 日志文件 | 运行日志、错误日志                   | 日志目录           | 可轮转     |

数据要求：

- 配置文件应可导入导出。
- 便携模式下所有数据应可保存在程序目录。
- 备份文件不得无限增长。
- 不应在未授权情况下上传用户数据。
